# 設計ドキュメント

## 1. 目的とスコープ

草野球のホームビデオ(YouTube にアップロード済み・固定カメラ・音声あり)から、
スコア記入の補助となる**打席タイムライン**を半自動生成する。

- スコア自体は人間がつける。本ツールは「早回しで結果を1つずつ探す」作業を置き換える
- 完全自動は目指さない。検出結果は候補であり、最終確認は人間

### 入力の前提

- 固定カメラ(三脚)。打球直撃などでまれに画角がズレる
- 音声あり。審判のコール・守備の掛け声・打撃音が判断材料として録れている
- 1試合 約1.5〜2時間

## 2. 設計原則

1. **ホワイトボックス優先**: 決定的に解ける処理はコードで実装(再現性・無料・デバッグ可能)
2. **LLM は曖昧さの解決専用**: 決定的シグナルで判定が割れた区間だけに使う(OpenAI API を予定)
3. **人力採点の判断材料をそのまま機械化する**: ユーザーが実際に使っている手がかり
   (審判の「アウト!」、守備の「ショート!」、打撃音)を検出器に落とす
4. **重い処理はネイティブ側**: デコード=ffmpeg、画素処理=OpenCV/NumPy、
   ASR=CTranslate2(faster-whisper)。Python はオーケストレーションのみ

## 3. 問題の構造

野球の試合映像は「投球」を原子イベントとして構造化できる:

```
試合 = イニング列 = 打席列 = 投球列 + 投球間イベント(盗塁・牽制・タイム)
```

打席の境界は「打者の交代」であり、**打者の人物クラスタリングが打席分割の中核**になる。
これはファール判定にも直結する:

- 接触音あり + 直後の活動が短い + 同じ打者が打席に残る → ファール
- 接触音あり + 活動が長い + 打者交代/塁上変化 → インプレーの結果

## 4. パイプライン

```
YouTube URL → yt-dlp → 映像 + 音声(16kHz mono WAV)

音声系(audio_events.py / speech.py):
  A1. 打撃音・捕球音検出   高域(2-7.5kHz)スペクトラルフラックスの MAD-z ピーク
  A2. Whisper 文字起こし   faster-whisper(ローカル CPU, vad_filter, 幻聴対策あり)
  A3. キーワード抽出       野球語彙ホワイトリスト照合(判定/守備位置/プレー/称賛)

映像系(motion.py):
  V1. 活動量計測          2fps サンプル、縮小グレースケール差分の平均
  V2. カメラズレ検出       位相相関によるグローバルシフト推定
  V3. 活動バースト抽出     MAD-z 閾値の連続区間

統合(timeline.py):
  F1. イベント融合         時刻軸にソート、語彙なし発話は除外(幻聴対策)
  F2. HTML/JSON 出力       youtu.be/ID?t=秒 のジャンプリンク付き
```

### 幻聴(hallucination)対策

Whisper は歓声・雑音で実在しない言葉を出力することがある。対策:

- `vad_filter=True` で無音・雑音区間を除外
- `condition_on_previous_text=False` で幻聴の連鎖を防止
- **語彙ホワイトリストに一致したセグメントのみ採用**(フル文字起こしを信用しない)
- `initial_prompt` に野球語彙・選手名を与えて固有名詞の認識率を上げる

## 5. 今後のステージ

### MVP②: 投球検出 + 打席グルーピング

- 捕球音(ミット音)+ ホームベース付近の定型的な動きから投球イベントを検出
- ホームベース領域の人物検出(ONNX の軽量検出器)→ 外見特徴で打者クラスタリング
- 打者交代を打席境界とする

### MVP③: ファール vs 結果の分類

- 決定的ルール(打者連続性・活動時間・キーワード)で大半を分類
- 判定が割れた区間のみ、前後クリップ+文字起こしを LLM(OpenAI, 構造化出力)で裁定

### MVP④: 攻守交代検出

- 長い中断 + フィールド全体の人の大移動 + 守備位置のユニフォーム色反転

### MVP⑤: 投球間イベント

- 投球時刻列の「隙間」で塁領域に活動がある区間を盗塁・牽制候補として差し込む

### 手動スコアとのアラインメント

`data/ground_truth/` の人力スコアはイベントの**順序付き列**なので、
検出イベント列との単調アラインメント(DTW 的な対応付け)により:

1. 各打席・各プレーへのタイムスタンプ付与(=最終目標の出力)
2. 検出器の精度評価(適合率・再現率)

が同じ仕組みでできる。スコア原文のパーサ(`score_parser.py`)を導入予定。

## 6. LLM 連携(未実装)

- プロバイダ: OpenAI API(ユーザー指定)。インターフェースは薄く保ちプロバイダ非依存に
- 用途: (a) 曖昧区間の裁定(クリップ静止画+文字起こし→JSON)、(b) スコア原文パース補助
- ASR は API ではなくローカル faster-whisper(長尺動画のコスト・レート制限対策)

## 7. 実行環境の注意

- YouTube ダウンロードは**ユーザーのローカル環境**で行う前提。
  データセンター IP からは PO Token / IP バインディングにより 403 になる
  (本リポジトリの開発中に実測)。ローカルで失敗する場合は
  `yt-dlp --cookies-from-browser` を使う
- 処理時間の目安(2時間動画): 打撃音検出 数十秒 / 活動量 数分 /
  Whisper small(CPU) 実時間の3〜5割。全段合わせて1時間弱を想定
